# Локальный ИИ-чат Manaschy

Актуальная реализация, 29 сентября 2026. Прежний эскиз облачного API и MockRagService заменён описанием работающего кода.

## Поток запроса

/chat → локальный читатель 127.0.0.1:8091 → подсказки Ollama → BM25 по четырёхтомнику → объяснение фрагментов → проверенные ссылки на страницы.

Модель: установленная qwen3.5:4b, только http://127.0.0.1:11434. Ключи API не читаются. Нет автоматической установки, загрузки модели, cloud API или выполнения команд модели.

## Поиск и достоверность

- Индекс охватывает 2 149 уникальных страниц, 42 раздела варианта Орозбакова (2018), не всю трилогию и не все варианты.
- До 30 кандидатов, до трёх фрагментов по 1 500 символов; максимум 4 500 символов источника (лучшее совпадение и непосредственно соседние фрагменты того же раздела). Далёкие совпадения не объединяются: модель смешивала разные события. Объём уменьшен после таймаута при шести фрагментах на локальном CPU. Нормализация не изменяет оригинал.
- Подсказки не считаются фактами. Объяснение должно опираться только на найденный текст; при недостатке данных предусмотрены not_found и clarify.
- Проверка структуры, идентификаторов и страниц не доказывает истинность каждого предложения. Возможны ошибки поиска, кыргызского понимания, перевода и выводов. Сверяйте источники.
- Ссылки строятся сервером из каталога, не принимаются от модели. Клиент проверяет их повторно.

## Ограничения и приватность

Вопрос до 2 000 символов; до восьми сообщений истории, в промпте суммарно до 4 000 символов; HTTP body до 32 КБ. Одна генерация одновременно, 12 запросов в минуту. Весь ответ ограничен 180 секундами, контекст 8 192 токенами, вывод объяснения 900 токенами; thinking отключён. Ошибочный или оборванный JSON не показывается как ответ.

Индекс и фрагменты находятся только в памяти службы. Диалог — в памяти приложения до перезагрузки/нового разговора. Приложение не пишет вопросы в журналы или на диск. При отсутствии локальных PDF загружаются фиксированные источники каталога; сайт получает технические данные запроса. Настройки журналов самой Ollama управляются пользователем отдельно.

Маршруты: GET /chat/status, POST /chat/prepare, POST /chat/messages. Сохраняются loopback-привязка, Host/Origin allowlist и проверки PDF. Health version 2 с reader/chat предотвращает использование старой службы.

## Запуск и область применения

Работающая Ollama с установленной моделью, затем `npm run web -- --port 8081`. Открыть /chat. Старую службу читателя нужно остановить вручную перед запуском новой версии; стартовый скрипт не завершает чужие процессы.

Статический экспорт содержит только UI и метаданные. На телефоне или публичном сайте потребуются отдельный сервис, защита доступа и проверка прав. Доступность PDF в интернете не является открытой лицензией на перепубликацию. Полный корпус не добавляется в git или клиентскую сборку.

Тесты: `npm run test:reader`, `npm run test:ci`; фактические результаты и ограничения — в [LOCAL_CHAT_VERIFICATION.md](LOCAL_CHAT_VERIFICATION.md).
