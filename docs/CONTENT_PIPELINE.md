# Content Pipeline — Manaschy

Описание полного процесса добавления контента в приложение.

## Принцип: Достоверность важнее скорости

Нельзя добавлять текст эпоса без:
- Подтверждённого источника.
- Проверенных прав использования.
- Экспертной проверки точности текста.
- Привязки к конкретному варианту / манасчи.

---

## Шаги добавления нового контента

### 1. Найти источник

Критерии хорошего источника:
- Официальное академическое издание (НАН КР и т.д.).
- Архивная рукопись с библиографическим описанием.
- Аудиозапись с подтверждёнными данными исполнителя.

НЕ использовать:
- PDF-копии из интернета без указания правообладателя.
- Сайты с агрегированным контентом без лицензии.
- Тексты без атрибуции.

---

### 2. Проверить организацию / издание

- Найти полное библиографическое описание: автор/составитель, издательство, год, место издания.
- Убедиться, что организация является авторитетной.
- Зафиксировать ISBN / архивный номер / каталожный номер.

---

### 3. Проверить права

Возможные статусы прав (`ContentRightsStatus`):

| Статус | Описание | Когда применять |
|--------|----------|----------------|
| `public_domain` | Общественное достояние | Произведения, у которых истёк срок авторской защиты; традиционный народный текст |
| `permission_granted` | Разрешение получено | Есть письменное разрешение от правообладателя |
| `citation_only` | Только цитирование | Источник цитируется, но полный текст не воспроизводится |
| `unknown` | Права не определены | Статус ещё не установлен — контент НЕ публикуется |
| `not_allowed` | Не разрешено | Явный отказ правообладателя |

**Важно:** эпический текст сам по себе может быть народным достоянием, но конкретное издание (редакторский труд, перевод, транслитерация) может иметь отдельную защиту. Уточнять у издателя.

---

### 4. Добавить source metadata

Добавить запись в `src/data/epic/sources.ts`:

```ts
{
  id: 'src-<org>-<desc>',
  title: '...',
  publisher: '...',
  year: 2000,
  language: 'ky',
  sourceType: 'book',
  reliability: 'academic',
  rightsStatus: 'unknown', // до получения разрешения
  citationText: 'Полная библиографическая ссылка...',
  verificationStatus: 'needs_review',
  notes: 'Дополнительные комментарии',
}
```

Обновить реестр в `docs/SOURCE_INVENTORY.md`.

---

### 5. Разбить на цикл

Определить, к какому циклу относится материал:
- `manas` — первая часть трилогии.
- `semetey` — вторая часть.
- `seytek` — третья часть.

Добавить или убедиться, что цикл есть в `src/data/epic/cycles.ts`.

---

### 6. Разбить на вариант

Определить манасчи / составителя и добавить или обновить запись в `src/data/epic/variants.ts`.

Правила:
- Один `variantId` — один исполнитель/составитель для одного цикла.
- Не смешивать тексты разных исполнителей в одном variantId.
- Если источник не подтверждён — `sourceStatus: 'needs_review'`.

---

### 7. Разбить на эпизоды

Взять оглавление из конкретного издания.

**Не выдумывать порядок.** Если оглавления нет — оставить placeholder и описать задачу в `docs/EPISODE_MAPPING_PLAN.md`.

Добавить эпизоды в `src/data/epic/episodes.ts`:

```ts
{
  id: 'manas-karalaev-001',
  cycleId: 'manas',
  variantId: 'manas-sayakbay-karalaev',
  order: 1,
  title: '...',
  shortDescription: '...',
  text: PLACEHOLDER_TEXT, // до подтверждения прав
  sourceStatus: 'needs_review',
  rightsStatus: 'unknown',
  sourceIds: ['src-nas-kr-karalaev-placeholder'],
  ...
}
```

---

### 8. Разбить на фрагменты (для RAG)

После подтверждения прав разбить эпизоды на фрагменты в `src/data/epic/fragments.ts`.

Каждый фрагмент:
- Ссылается на `episodeId`, `variantId`, `cycleId`.
- Имеет `sourceIds`.
- Начинает с `sourceStatus: 'needs_review'`.

---

### 9. Отдать эксперту на проверку

- Текст сверяется с оригинальным изданием.
- Проверяется правильность разбивки на эпизоды.
- Проверяется корректность атрибуции.

---

### 10. Финальная верификация

После одобрения эксперта:
- Установить `sourceStatus: 'verified'` на соответствующем источнике.
- Установить `rightsStatus: 'public_domain' | 'permission_granted'` после подтверждения прав.
- Запустить `npm run content:validate` и `npm run sources:validate`.
- Только после этого AI сможет использовать фрагменты.

---

## Инструменты

```bash
# Проверить источники
npm run sources:validate

# Проверить контент
npm run content:validate

# Импортировать из manifest (после получения прав)
npx tsx scripts/content/import-manifest.ts data/manifests/example.json
```

## Структура файлов

```
src/data/epic/
  cycles.ts        — 3 цикла трилогии
  sources.ts       — реестр источников
  variants.ts      — варианты / манасчи
  episodes.ts      — эпизоды
  fragments.ts     — фрагменты для RAG
  audio-tracks.ts  — аудиодорожки
  index.ts         — re-exports

data/
  raw/             — исходные файлы (PDF, текстовые файлы, аудио)
  imported/        — обработанные и верифицированные данные
  manifests/       — JSON manifests для import-manifest.ts

scripts/content/
  validate-sources.ts   — проверка источников
  validate-content.ts   — проверка контента
  import-manifest.ts    — импорт из manifest

docs/
  SOURCE_INVENTORY.md   — реестр источников
  EPISODE_MAPPING_PLAN.md — план разметки эпизодов
  AI_API_PLAN.md        — архитектура AI/API
  CONTENT_PIPELINE.md   — этот файл
```
