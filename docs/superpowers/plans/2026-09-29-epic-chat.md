# Epic Chat Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Добавить общий локальный чат, который ищет описанный пользователем момент во всех четырёх доступных томах «Манаса», объясняет найденный текст и открывает страницы источника.

**Architecture:** Существующая loopback-служба читателя хранит временный поисковый индекс в памяти и обращается к установленной Ollama. Поисковые подсказки модели отделены от фактов источника; ответы проверяются по структуре и идентификаторам найденных фрагментов. Expo-страница отображает переписку, подготовку, ошибки и ссылки, не получая полный индекс.

**Tech Stack:** Expo SDK 56, React Native/React Native Web, TypeScript, Node.js ESM, установленный PDF.js, Ollama `qwen3.5:4b`, существующие Jest/Testing Library и `node:test`. Новые зависимости и модели не требуются.

**Spec:** `docs/superpowers/specs/2026-09-29-epic-chat-design.md`

## Global Constraints

- Перед продуктовым кодом прочитать точную документацию `https://docs.expo.dev/versions/v56.0.0/`, как требует `AGENTS.md`.
- Область поиска — весь доступный в проекте кыргызский текст четырёхтомного издания варианта Сагымбая Орозбакова, 2018 год: 42 раздела.
- Новый маршрут `/chat`; выбирать эпизод, том или страницу перед вопросом не требуется.
- Используется существующая локальная Node-служба читателя на `127.0.0.1:8091`.
- По умолчанию только Ollama на `http://127.0.0.1:11434`, модель `qwen3.5:4b`.
- Облачные модели, API-ключи из окружения и сторонние серверы не используются.
- Вопрос до 2 000 символов, до восьми предыдущих сообщений, тело запроса до 32 КБ. Разрешены только роли пользователя и помощника, язык RU/KY.
- Одна генерация одновременно, не более 12 запросов сообщений в минуту на локальную службу.
- Ограничены время обработки (180 секунд на вопрос), число выходных токенов (до 900 на объяснение) и контекст (8 192 токена). Режим thinking отключён.
- Из первых 30 кандидатов выбирается до шести релевантных фрагментов с ограниченным соседним контекстом, всего не более 12 000 символов источника.
- Фрагменты, поисковый индекс и промежуточные данные находятся только в памяти процесса. Постоянное сохранение переписки не добавляется.
- Переход к источнику использует `/episode/<id>?page=<номер>`.
- Рабочий запуск этой версии — web на компьютере пользователя; статический экспорт не содержит модель, книги или Node-службу.
- В рабочем дереве уже много пользовательских изменений. Не сбрасывать их, не использовать массовый `git add`, не переносить весь грязный файл в коммит. Коммиты задач должны содержать только свои новые файлы/изолированные изменения; если отделить старые правки нельзя, оставить смешанный файл незакоммиченным и отметить это.

## Review Focus

1. Русский пересказ события, кыргызские имена с окончаниями и смешанные латинские/кириллические глифы: поиск нормализует ключи, не искажает показанный оригинал; тест задачи 1.
2. Один недоступный том или два одновременных открытия чата: нет ложной полной готовности и дублирующей индексации; тест задачи 1.
3. Поддельная ссылка, инструкция внутри PDF или огромная история: модель не меняет адрес сервера, не выполняет команды, ответ и контекст ограничены; тесты задач 2–3.
4. Отмена, «Новый разговор» и поздний ответ: старый запрос не заполняет новый диалог и освобождает занятость сервера; тесты задач 3–4.
5. Другая ссылка на страницу того же эпизода и возврат назад: читатель меняет страницу, чат не теряет переписку; тест задачи 5.

## Карта файлов и контрактов

Сервер:
- `scripts/reader/source-page.mjs`: добавить ограниченный итератор страниц с прежними проверками PDF.
- `scripts/reader/chat-index.mjs`: фрагменты, фоновая подготовка, BM25 и отбор контекста.
- `scripts/reader/chat-ollama.mjs`: только локальные HTTP-вызовы Ollama, ограничения и структурированные ответы.
- `scripts/reader/chat-answer.mjs`: поиск, объяснение, проверка ссылок и сборка ответа.
- `scripts/reader/chat-http.mjs`: валидация запросов, маршруты, занятость, лимиты, отмена.
- `scripts/reader/server.mjs`: подключить маршруты после существующей проверки Host/Origin; сохранить чтение страниц.
- `scripts/start.mjs`: проверять версию/возможности службы перед повторным использованием порта.

Клиент:
- `src/features/chat/types.ts`, `api.ts`, `store.ts`, `messages.ts`, `chat-screen.tsx`: контракт, транспорт, непостоянная сессия, RU/KY, экран.
- `src/app/(tabs)/chat.tsx` и существующая навигация: отдельная доступная страница.
- `src/app/episode/[id].tsx`, `src/features/episodes/reader-screen.tsx`: проверенные ссылки на нужную страницу.
- `src/i18n/ru.ts`, `ky.ts`: название вкладки и актуальная информация о локальном ИИ/приватности.

Общие формы данных (сервер описывает их JSDoc, клиент — TypeScript):
```ts
type ChatLocale = 'ru' | 'ky';
type ChatTurn = { role: 'user' | 'assistant'; content: string };
type ChatRequest = { question: string; locale: ChatLocale; history: ChatTurn[] };
type ChatSource = { id: string; episodeId: string; title: string; volume: number; page: number; href: string };
type ChatReply = { status: 'answered' | 'clarify' | 'not_found'; answer: string; sources: ChatSource[] };
type ChatStatus = {
  index: 'idle' | 'preparing' | 'ready' | 'error';
  model: 'ready' | 'unavailable' | 'missing';
  completedPages: number; totalPages: number; error?: string;
};
```
Сервер не принимает и не выдаёт произвольный `href`: он строится из каталога.
Ответ `answered` требует хотя бы один допустимый источник; `not_found` не имеет ссылок.
