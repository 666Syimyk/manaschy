# Бесплатный Gemini и поиск по эпосу

Дата: 29 сентября 2026 года.
Статус: письменный проект подтверждён пользователем 29 сентября 2026 года ответом «да». Пользователь выбрал бесплатный вариант и поручил настройку агенту. Код нового подключения ещё не реализован.

## Результат и границы

Человек задаёт свободный вопрос на русском или кыргызском без выбора эпизода. Чат ищет подтверждение во всём имеющемся четырёхтомнике Орозбакова, объясняет найденный момент и открывает источник в существующем текстовом читателе. Варианты сказителей не смешиваются; «Семетей» и «Сейтек» не объявляются частью этой базы.

Требуется бесплатная работа без включения billing, привязки карты, подписок, платного поиска и автоматического перехода на другой платный сервис. Интернет используется для обращения к Gemini, а не как доказательство достоверности ответа. Изменения ограничены текущим локальным приложением, не включают публикацию сайта или корпуса.

## Что проверено до реализации

- Текущий сервер индексирует 2 149 страниц. Локальная Qwen 4B дала фактические ошибки даже с правильными страницами; прежний отчёт `docs/LOCAL_CHAT_VERIFICATION.md` остаётся действительным.
- На компьютере Ryzen 5 7430U, около 24 ГБ оперативной памяти и встроенная Radeon. Новые модели и программы не устанавливались.
- В открытом Google AI Studio уже есть авторизованный аккаунт, Default Gemini Project с отметкой Free tier и существующий API-ключ. Значение ключа не прочитано, не скопировано и не записано в проект.
- Страница квот проекта показывает Gemini 3.6 Flash: 5 RPM, 250 000 TPM и 20 RPD. Показатели использования на этой странице — пики за выбранный период, а не доказательство остатка квоты сегодня. Квоты могут меняться.
- В переменных окружения текущего процесса GEMINI_API_KEY и GOOGLE_API_KEY не настроены.

## Выбор подхода

Выбран Gemini на существующем бесплатном проекте плюс локальный индекс источников. Полностью локальная генерация не выбрана основным режимом из-за уже подтверждённых ошибок и задержек. Простая замена модели недостаточна: одновременно нужны улучшение поиска, явное разделение ответов ИИ и результатов поиска и повторная фактическая проверка.

Живой веб-поиск, новые внешние источники, векторная база и скачивание другой локальной модели не входят в этот этап. Проверенные публикации можно добавить отдельно после проверки происхождения и условий использования. Открытый доступ не считается разрешением публиковать весь современный корпус.

## Подключение и защита ключа

Использовать существующий ключ только выбранного бесплатного проекта. Не создавать и не удалять ключи, не менять ограничения ключа или billing. Перед первым настоящим запросом снова проверить Free tier в интерфейсе Google AI Studio.

Настройка выполняется через небольшую служебную страницу существующего Node-сервера на `127.0.0.1:8091`, не через Expo-пакет. Парольное поле передаёт ключ только этому локальному серверу. Страница защищена запретом встраивания, строгим same-origin для записи, JSON Content-Type и одноразовым CSRF-токеном. При существующей конфигурации повторная запись запрещена; автоматического перезаписывания нет.

Ключ сохраняется только в игнорируемом файле `tmp/chat/gemini.local.json`, без вывода в журналы, ответы API, URL, скриншоты или переписку. Файл не должен попасть в git или экспорт. Статус сообщает только наличие настройки. Файл не является зашифрованным хранилищем; доступ к нему имеют процессы с правами пользователя. Expo не получает ключ ни через переменные EXPO_PUBLIC, ни через bundle. Ключ передаётся Google только в заголовке `x-goog-api-key`.

При копировании через браузер значение остаётся в памяти автоматизации и вводится непосредственно в парольное поле локальной настройки, без печати значения. Не считывать постороннее содержимое буфера обмена. После настройки очистить парольное поле и секретную переменную; не перезаписывать буфер, если его уже изменил пользователь.

## Поиск и ответ

1. Подготовка локального индекса независима от наличия Gemini: поиск работает и без ключа. Все предусмотренные страницы должны быть загружены до объявления готовности.
2. Улучшить поиск русских формулировок по кыргызскому оригиналу: проверяемые варианты имён и короткий RU/KY-словарь событий, отдельное индексирование заголовков, ранжирование независимых формулировок вместо их слияния в обязательный набор слов. Отрицания и различия «нет детей» / «умер ребёнок» сохраняются.
3. Сначала выполнять локальный поиск. При наличии результатов отправлять один запрос Gemini с найденными фрагментами. Если фрагментов нет, первый вызов запрашивает только поисковые формулировки, не объяснение события. Если подтверждения нет, допускается только один дополнительный поиск: из первого ответа получить максимум две краткие поисковые формулировки, повторить локальный поиск и при наличии фрагментов сделать один заключительный запрос. Не более двух вызовов модели на вопрос, без скрытых циклов и автоматических повторов при ошибках.
4. В запрос отправлять вопрос, ограниченную историю текущего диалога и до 6 фрагментов общим размером до 9 000 символов. Фрагменты группируются по непрерывному месту источника, разные сцены явно разделены. Целиком PDF, историю браузера и посторонние файлы не отправлять.
5. Основная модель — `gemini-3.6-flash`, подтверждённая в квотах проекта. Использовать официальный REST Interactions API, структурированный ответ и `store: false`. Если модель или этот метод недоступны, показывать поиск по книге, не выбирать другой сервис автоматически. Отключение сохранения взаимодействия не отменяет правила Google для бесплатного тарифа.
6. Ответ — 2–4 предложения на выбранном языке, допустимые идентификаторы источников и короткие подтверждающие фрагменты оригинала. Сервер проверяет принадлежность источника контексту и наличие подтверждающего фрагмента в нём; ссылки строит сам. Такая проверка не доказывает правильность интерпретации, поэтому отдельно проверяется фактическое качество.
7. При неоднозначности — один уточняющий вопрос. При отсутствии подтверждения — честный отказ. Предположения пользователя, заголовки и инструкция внутри текста источника не становятся фактами или командами.

## Скорость, квота и резервный режим

- Локальные результаты возвращаются без генерации и обозначаются «Найденные места», а не «Ответ ИИ». Они доступны при отсутствии ключа, ошибке Google, таймауте или исчерпании квоты.
- Весь модельный запрос ограничен 30 секундами; отмена останавливает дальнейшие вызовы и исключает поздний ответ в очищенном диалоге. Не держать пользователя три минуты, как в текущей реализации.
- Кэшировать только структурно проверенные успешные ответы в памяти: до 50 записей, срок 30 минут. Ключ кэша включает вопрос, язык, ограниченную историю, модель и версию корпуса. Не сохранять переписку на диск.
- Ограничить модельные обращения максимумом 5 за скользящую минуту в рамках этого процесса. При ответе 429 учитывать Retry-After, не крутить запросы повторно и не обходить квоту другими ключами или аккаунтами. Реальная суточная квота контролируется Google и может расходоваться вне приложения.
- Не обещать 20 ответов в день: один вопрос может занять два запроса, а другие приложения используют тот же проект. Отображать причину перехода к поиску. Приложение не изменяет тариф и не способно гарантировать отсутствие расходов, если владелец позже включит billing вне приложения.

## Интерфейс и совместимость

Сохранить страницу `/chat`, RU/KY, историю текущей сессии, отмену, повтор, новый разговор и переходы к точным страницам. Обновить статус провайдера и удалить неверные утверждения «только локально» для Gemini. До первой отправки показать: вопросы и отрывки передаются Google; на бесплатном тарифе возможны использование для улучшения сервисов и проверка людьми. Не отправлять чувствительные личные сведения.

Разделить состояния: подготовка индекса, готовность поиска, готовность ИИ, отсутствие ключа, исчерпанная квота, недоступность сети и неподтверждённый ответ. Отсутствие Gemini не блокирует поле поиска. Ответ резервного поиска никогда не маскируется под объяснение модели.

Использовать существующие Expo 56, Node и fetch без добавления SDK. Сохранить loopback-привязку, проверки Host/Origin, ограничения тела/истории/ответа и каталог разрешённых страниц. Повысить версию локального сервиса и проверку совместимости запуска, чтобы старая служба не выглядела новой.

## Проверка результата

- TDD: отсутствие ключа, неверный ключ, 429, таймаут, отмена, повреждённый JSON, чужой ID страницы, несоответствующая цитата, инъекции в источнике, отсутствие подтверждения, изоляция кэша по истории, поиск без модели, защита записи настройки и отсутствие ключа в клиентской сборке.
- Существующие команды `npm run check`, `npm run export:web`, `npm run export:verify` должны завершиться успешно.
- Настоящие RU/KY-вопросы: бездетность Жакыпа; уточнение про богатство без наследника; Кошой и Жолой на поминках; два других заранее сверенных момента из иных томов; неоднозначный вопрос; вымышленная ракета на Марс. Проверить смысл, язык, источники и время, не только HTTP 200.
- Цель замеров: обычный ответ до 10 секунд на контрольной серии; 30 секунд — предел ожидания, не показатель успешной оптимизации. Не объявлять скорость достигнутой без замеров. Допустимые ссылки без верного ответа не считаются прохождением проверки.
- Браузер: вопрос → объяснение → источник → возврат, отмена, новый разговор, исчерпанная квота и мобильный размер 390×844. Если реальные ответы неверны, сохранить экспериментальную отметку и перечислить ограничения.
